One skill, one CLI: a crew of agents for your repository.

ACE builds workspaces for autonomous coding agents. You point your agent at this repository; it loads the ace skill, reads what your repo already says about itself, and runs ace setup — one command writes the whole arrangement: a Herdr tab per project plus a control plane, one Ego Lite browser space per project, a governor over a global worker budget, one supervisor and its workers per project with the outcome on every task, durable memory per tree, and the handoff convention every mission ends with. One name holds it together — project.id === its tab label === its browser space === basename(its tree).

$ ace parts

Seven parts, and none of them is usable alone. Each one hands an exact name to the next, so the terminal, the browser, the disk and the governor's report all call a project the same thing.

agent-skillthe manual the workspace's own agent loads, copied into every harness's skills directory. Three copies of one shipped source — verified identical.
herdr-spacesone tab per project, plus a control-plane tab holding the governor and one supervisor per project. The number of tabs is always 1 + the number of projects.
ego-lite-spacesone browser space per project, named after the project's own tree. A second space is never opened to escape a stuck page.
governone governor over a global worker budget: it checks liveness and evidence-backed progress, swaps an unusable model route for a validated one, and escalates what it cannot recover.
supervisors-workersexactly one supervisor per project and its workers — and every task declares the outcome it produces, or it is refused at dispatch.
accdurable memory per tree: a control file and one .acc-memory.md beside each project, so a new session starts informed instead of re-learning the repo.
charterthe layer on top: the task contract, the handoff convention every mission ends with, and the registry of tools the crew may use.
the rule, and the seven lines setup prints under linked 
project.id === its tab label === its browser space === basename(its tree)

agent-skill         → herdr-spaces:        the driver
herdr-spaces        → ego-lite-spaces:     project.id
ego-lite-spaces     → herdr-spaces:        browser_space
govern              → supervisors-workers: cap
supervisors-workers → charter:             tasks[].outcome
acc                 → govern:              memory
charter             → supervisors-workers: acceptance

That first line is the whole boundary system. It is not a convention anyone has to remember: ace setup refuses a setup whose names would disagree — a project root that does not exist, two trees that collide on one id, an agent name the multiplexer cannot attach — and the installed selftest.mjs fails on a project whose space stops matching its id.

Every field is data: adding a project, a worker or a task is an edit to this file, never a branch in the orchestrator. An empty tasks list is allowed; a task without an outcome is not — the outcome line is what the supervisor reads before it dispatches, and the governor ranks the next outcome across the whole portfolio.

A worker's claim is not a result: a handoff that says DONE without a command, a file path or a measurement is recorded unverified, and an artifact written outside the mission's own project directory is an isolation violation that closes nothing. Every refusal is written down with its reason, the same way the cap records the spawn it declined.
