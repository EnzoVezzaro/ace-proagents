$ the problem you already have

Three agents, maybe five, across two or three work areas. The thing holding them together is you: a terminal tab per project that you rename when one dies, a browser profile you hope is the right one, a note about which agent owns which tree, a worker budget nobody enforces.

A supervisor stalls on Tuesday; you notice on Thursday. A worker reports done; the integrated build is red. A model silently falls back to a paid tier; the invoice explains it a week later. A new session spends its first twenty minutes re-learning what the last one already knew.

None of that is a discipline problem. It is an arrangement problem — and an arrangement can be written down, enforced in code, and verified before anything claims to be done.

$ the fix — seven parts, one name

the invariant every part reads — enforced in code, not by prompt 
project.id === its tab label === its browser space === basename(its tree)

A project is one name in the terminal, in the browser, on disk and in the governor's report — so there is exactly one place to look for what it touched. The seven parts that make that real, each framed as what it buys you:

agent-skillthe workspace teaches its own operator. The manual installs beside the crew — into .agents/skills/, .claude/skills/, .opencode/skills/ — so the next agent starts competent, not curious.
herdr-spacesan office, not a tab list. One tab per project plus a control plane — always 1 + N, derived from data. Adding a project adds one tab; nobody re-edits a config by hand at midnight.
ego-lite-spacesbrowser work stays in its lane. One space per project, named after the project. A stuck page never pushes a worker into someone else's session.
governa stalled supervisor is noticed in minutes, not Thursday. One governor over a global budget checks liveness and evidence-backed progress, swaps dead model routes, and escalates what it cannot fix.
supervisors-workersno task without an outcome. Every task names the outcome it produces before it is dispatched; one owner per task, lease-backed. A crew that cannot say what "done" means does not start.
accthe next session starts informed. Durable memory per tree — gotchas, decisions, lessons — seeded once, never overwritten. Twenty minutes of re-learning becomes thirty seconds of reading.
charterDONE means evidence. The handoff convention every mission ends with: files changed, commands run, results, failures, what was not tested. A claim with nothing behind it is recorded unverified — by the machine, not by your mood.
how the parts hand off — each link carries one exact name 
agent-skill         → herdr-spaces:        the driver
herdr-spaces        → ego-lite-spaces:     project.id
ego-lite-spaces     → herdr-spaces:        browser_space
govern              → supervisors-workers: cap
supervisors-workers → charter:             tasks[].outcome
acc                 → govern:              memory
charter             → supervisors-workers: acceptance

This is why "just write some scripts" loses: scripts arrange, they don't refuse. Here a setup whose names would disagree is refused at install time, an agent named for a project it doesn't own cannot be spawned, and a handoff that lies fails a check — the invariants are code with tests, not conventions with intentions.

$ drive it

After the install, the crew is data and commands — the same words your agent already knows how to run. Nothing here needs a dashboard.

ace inspect --jsonthe repo's facts — work areas, verification scripts, git state — before anything is answered
ace setup --dry-runthe whole plan, writing nothing. You read it before your repo changes
ace setup --jsoninstall and verify. One JSON document out; structured refusals that name the fix
tabs.mjs planthe roster and the budget with its source — who runs, where, and why that number
tabs.mjs upinside the multiplexer: create the tabs, start the agents that fit the cap
tabs.mjs governthe governor's brief across every project — liveness, evidence, what's next
tabs.mjs verify · cyclehandoffs checked against evidence; recovery recheck; the next task, or an honest "none"
ace task add "…" --outcome "…"a task with no outcome line is refused at the door
ace handoff verify a DONE claim with no command that exited 0 does not pass
ace watchdog cyclean independent control plane recovers a dead governor — the governor is not a single point of failure

Adding a project, a worker or a task is an edit to this file — never a branch in the orchestrator. The boundaries are visible right here: owned_paths is where a project's agent may write, forbidden_paths is everything else. When a spawn exceeds the cap, the refusal is logged with its reason — the budget you set is the budget that holds.

$ the objections, answered

will this burn tokens?no. The install starts nothing, sends nothing, opens nothing. When the crew runs, work is dispatched only to models whose freeness is verified this run — a name containing -free is not evidence. With nothing verified, the dispatch is refused, not billed.
does it work with my harness?the skill installs into .agents/skills/ (the cross-harness location), .claude/skills/ and .opencode/skills/ — one source, three copies, verified identical. Codex, Copilot, Cursor and Gemini CLI read AGENTS.md: point them at the same file. The agents themselves run on opencode, claude, codex, gemini or freebuff panes.
do I need the Herdr multiplexer?to install, plan, verify and read state: no — all offline. To create tabs and start agents: yes, tabs.mjs up runs inside a Herdr session, and the install says so plainly rather than pretending.
what happens to my files?writes stay inside your repository: the orchestration stack, generated data, memory files, charter, one merged ace key. A file that already exists and differs is left alone unless you pass --force. Memory is seeded once and never overwritten — not even with --force. Nothing is published, pushed or deployed, ever.
am I locked into a model or vendor?no route is written unless you pin one. The model, the multiplexer, the memory layer — every third-party capability is an adapter with a contract, and deterministic fakes ship in the box so the tests need no credentials.
what if it breaks mid-run?recovery is bounded and audited: checkpoint first, hold the lease, respect the restart budget, journal every action to .ace/actions.jsonl. A heartbeat alone never proves progress, and nothing reports a restart it did not deliver. When the chain is exhausted, it escalates to you instead of pretending.
why not just write my own scripts?you would re-derive seven linked parts, each with a verifier — and your scripts will not refuse a lying handoff at 2am. Every check here exists because a crew without it failed quietly: the refusals are the feature.

What is genuinely absent, stated plainly: no HTTP API yet (the CLI's --json surface is the machine interface), no live provider quota check, no hosted service. See docs/APP-INTEGRATION.md for exactly what a UI could consume today.
