Every governance command takes --json: one document on stdout, or one structured error on stderr. Exit 1 means an operator must act, 2 a usage or configuration error. These ship in the repository now (v0.1.3); the npm release still serves v0.1.2, which predates the governance layer.

A heartbeat is not proof of progress. The same cycle with no heartbeat, or with a heartbeat but no movement in the window, reports SUPERVISOR_ABSENT or a stalled supervisor, plans recovery, and escalates to the operator when it cannot deliver one — the report says delivered: false rather than claiming a restart that did not happen.

hierarchy
governor → supervisor → worker
active agents
4 per project by default · raisable, not a ceiling · one budget across runtimes
boundary
the governor never messages a worker — refused in policy, not by prompt
failover
validated fallback routes · bounded restarts · backoff · escalation
watchdog
a control plane outside the governor, so a dead governor is still recovered
adapters
11 swap points · 34 providers, including deterministic fakes for tests
isolation
worktrees · bounded write scopes · one owner per task
management bots
experimental · off by default · intake cannot bypass the budget
interface
the CLI and its --json documents · no HTTP API yet

Each line above is a command in this package: ace crew, ace govern --json, ace watchdog status, ace task list --json, ace adapters audit, ace bots status. What is not implemented is listed as plainly: no HTTP API, no live management-bot transport, no provider quota check — see docs/APP-INTEGRATION.md.
