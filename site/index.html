Six parts, one name: a crew of agents for your repository.

One CLI. ace setup asks what the work is, reads what your repository already says about itself, then writes the whole arrangement: a Herdr tab per project plus a control plane, one Ego Lite browser space per project, a governor over a global worker budget, one supervisor and its workers per project with the outcome on every task, durable memory per tree, and the handoff convention every mission ends with. The parts are held together by one name — project.id === its tab label === its browser space === basename(its tree).

$ ace parts

Six parts, and none of them is usable alone. Each one hands an exact name to the next, so the terminal, the browser, the disk and the governor's report all call a project the same thing.

herdr-spacesone tab per project, plus a control-plane tab holding the governor and one supervisor per project. The number of tabs is always 1 + the number of projects.
ego-lite-spacesone browser space per project, named after the project's own tree. A second space is never opened to escape a stuck page.
governone governor over a global worker budget: it checks liveness and evidence-backed progress, swaps an unusable model route for a validated one, and escalates what it cannot recover.
supervisors-workersexactly one supervisor per project and its workers — and every task declares the outcome it produces, or it is refused at dispatch.
accdurable memory per tree: a control file and one .acc-memory.md beside each project, so a new session starts informed instead of re-learning the repo.
charterthe layer on top: the task contract, the handoff convention every mission ends with, and the registry of tools the crew may use.
the rule, and the six lines setup prints under linked 
project.id === its tab label === its browser space === basename(its tree)

herdr-spaces        → ego-lite-spaces:     project.id
ego-lite-spaces     → herdr-spaces:        browser_space
govern              → supervisors-workers: cap
supervisors-workers → charter:             tasks[].outcome
acc                 → govern:              memory
charter             → supervisors-workers: acceptance

That first line is the whole boundary system. It is not a convention anyone has to remember: ace setup refuses a setup whose names would disagree — a project root that does not exist, two trees that collide on one id, an agent name the multiplexer cannot attach — and the installed selftest.mjs fails on a project whose space stops matching its id.

Every governance command takes --json: one document on stdout, or one structured error on stderr. Exit 0 installed and verified · 1 a check failed, or an operator must act · 2 a usage, intake or plan error — nothing written. With no answers and no terminal, ace setup refuses with INTAKE_INVALID and names every missing field instead of guessing. ace setup and ace parts are on origin/main and in the published package (npm 0.1.4); the v0.1.3 tag predates them. CI is green on Node 20 and Node 22, including the step that installs into a scratch repo and runs the proof it wrote there.

Twenty-one paths were written in that run: the eighteen above, the ace key merged into package.json, and one .acc-memory.md inside each project tree. The modules under orchestration/lib/ and tabs.mjs are copied verbatim from the package's assets/stack/ — the generic copy the installer ships, which is a sibling of the project's own orchestration/ rather than the same file (the shipped free-models and cap carry their own sources): docs/STACK.md maps which is which. Everything else is generated from your answers: projects.json, the ace key, the ACC files, the charter layer and STACK.md. The install starts no agent, creates no tab, opens no browser space and invents no model route; it writes nothing outside your repository, and it never publishes or pushes.

A worker's claim is not a result: a handoff that says DONE without a command, a file path or a measurement is recorded unverified, and an artifact written outside the mission's own project directory is an isolation violation that closes nothing. Every refusal is written down with its reason, the same way the cap records the spawn it declined.
